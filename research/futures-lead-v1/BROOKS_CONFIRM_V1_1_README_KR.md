# 빗썸 브룩스 확인 진입 연구 V1.1

**독립 연구판, 자동주문·실전 BUY 알림 없음.** 기존 `/classic` V1.0, G형 및 다른 스캐너를 바꾸지 않습니다.

## 목표

기존 브룩스형 H2 신호 하나마다 다음 두 가상 진입을 비교합니다. 실제 Al Brooks의 검증된 계좌 매매 기록이 아니라, V1.0에서 정량화한 브룩스형 신호입니다.

- **기본 진입(B):** 신호 5분봉 종료 후 다음 완료 5분봉의 종가에 진입한다고 가정합니다. V1.0과 동일합니다.
- **확인 진입(C):** 기본 진입 대상 봉의 `종가 > 시가` **그리고** `종가 > 신호 봉 종가`이면 상승 완료로 판정하고, **그 다음 5분봉 종가**에 가상 진입합니다. 조건에 실패하면 미거래로 표시하고 0% 정책값을 계산합니다. 미거래는 승리·손실로 세지 않습니다.
- 모든 신호는 동일한 1시간봉 완성 조건, 거래대금, 신호별 3시간 쿨다운 및 하루 최대 4회 조건을 공유합니다. 같은 신호 안에서 기본 성과와 확인 진입 성과를 비교하므로 확인 진입만 선별해 유리하게 보이지 않습니다.

## 모의청산 가정

왕복 수수료 **0.50%**, 슬리피지 **0%**, 순익 목표 **+0.50%**, 가격 기준 손절 **-1.00%**, 진입 이후 **최대 60분**입니다. 이후 완성된 각 5분봉 **종가**로만 익절·손절을 판정하며, 고가·저가의 가상 체결을 주장하지 않습니다. 확인 진입은 기본 진입보다 정확히 5분 늦어지고, 60분 보유 시간은 각자의 진입부터 독립 계산합니다.

## 통계 해석

1. `base_all`: 모든 선택 신호에서 기본 진입의 성과.
2. `base_matched` 와 `confirmed_only`: **똑같이 확인 성공한 신호들**에서 진입 시점만 다르게 한 공정 비교.
3. `skipped_base`: 확인 조건 때문에 건너뛴 신호들의 **원래 진입 성과**. 이 그룹에 수익이 많으면 확인 필터가 좋은 기회를 놓친 것입니다.
4. `confirmed_policy`: 신호가 있었으나 확인 실패하면 0% 수익으로 처리한 **신호당 평균**. 실제 거래당 평균 수익이 아니며 미거래 횟수도 별도로 보고합니다.
5. 날짜별 신호 0건은 0으로 표시합니다. 시계열의 최종 날짜는 일부만 수집된 날짜일 수 있습니다.

## 진단 항목과 V1.0 차이

요청한 전체 6일·13일 구간 기준 코인별 기대 5분봉, 실제 5분봉, 누락봉, 조회 상태 및 오류를 별도 CSV로 기록합니다. 신규 상장/저유동성 종목의 누락봉을 추정 가격으로 채우지 않습니다.

**V1.1은 V1.0과 달리 24시간 거래대금에 사용한 288개 분봉이 시간상 모두 연속인지 확인합니다.** 또한 확인 진입 이후 60분을 완전히 관측해야 하므로 추가로 마지막 5분이 검증 가능해야 합니다. 따라서 과거 V1.0 거래 수와 1:1 같지 않을 수 있습니다. 이번 V1.1 내의 B/C 쌍끼리 비교해야 합니다.

데이터 접근 제한 HTTP 418/429 발생 시 재시도하지 않으며, 오류와 남은 종목 미조회를 분리합니다. 10분 같은 설정 반복 실행은 최근 결과를 재사용합니다.

## 로컬 실행

같은 폴더에 `classic_priceaction_lab.py`, `brooks_confirm_lab_V1_1.py`, `test_brooks_confirm_V1_1.py`를 둡니다. Python 3.9+ 표준 라이브러리만 사용합니다.

```sh
python brooks_confirm_lab_V1_1.py --selftest
python brooks_confirm_lab_V1_1.py --web --port 10021
python brooks_confirm_lab_V1_1.py --coins BTC,ETH,XRP --days 6
```
