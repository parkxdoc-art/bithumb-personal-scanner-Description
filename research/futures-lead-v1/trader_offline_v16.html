파일을 브라우저 안에서만 분석합니다. 파일 원본은 Render 서버로 전송하지 않으며, 데이터 조회·지갑 연결·카피 거래는 하지 않습니다. 지갑 별칭만으로 실제 인물을 인증하지 않습니다.

1. 거래 기록 파일 선택

Hyperliquid 체결 내역 CSV/JSON 또는 이미 진입·청산 정보가 정리된 거래 CSV를 선택해 주세요. 여러 파일을 한 번에 선택할 수 있습니다. 파일 하나당 한 지갑 기록을 권장합니다.

지원하는 원본 파일 형식과 제한
  • 원시 체결: time,coin,side,px,sz,startPosition,closedPnl,fee 필요. JSON 배열도 가능. 선택적으로 wallet,feeToken,tid,dir 지원
  • 완결 거래: coin,side,entry_kst,exit_kst,net_proxy_usdc 또는 동등한 영문 필드 필요. 원시 체결과 섞여 있으면 형식별로 처리
  • 원시 체결의 포지션 시작·종료가 파일 안에 모두 있어야 왕복 거래로 인정. 누락 구간·부분 청산·포지션 방향 전환은 보수적으로 처리
  • 숫자 UNIX 시각/시간대가 붙은 시각이 우선입니다. 시각에 시간대 표시가 없으면 원시 체결·entry_time은 UTC, entry_kst는 한국시간으로 해석합니다
  • 최대 파일 5MB, 최대 50,000행/파일, 최대 12개 파일. ZIP과 V1.5.1 진단 CSV는 분석하지 않음
  • 수수료 단위가 USDC가 아닌 체결은 분석에서 제외. 수익률 대신 계좌 전체와 다른 USDC 추정 손익만 제공

2. 실제 파일 분석 결과

파일·지갑별 수집 상태

구분파일원본 행복원 거래단타 거래누락/제외비고

트레이더별 결과 (5~240분)

관측 대상단타롱/숏승률*중위 보유분순손익 추정 합계(USDC)최대 손실(USDC)

보유시간별 거래 분포

보유시간거래 건수승률*순손익 추정 합계(USDC)

왕복 거래 상세 최신 100건 표시, CSV는 전체 출력

관측 대상코인롱/숏진입(KST)청산(KST)보유분추정 순손익출처

* 승률: 선택한 5~240분 거래의 USDC 추정 순손익이 양수인 비율. 퍼센트 수익률·계좌 수익률이 아닙니다. 펀딩, 미관측 헤지, 누락된 거래 및 원본 데이터 신뢰성은 별도 검증이 필요합니다.

3. 원본 거래 기록 구하는 방법

Hyperliquid 앱의 Trade History에서 CSV 내보내기를 사용할 수 있어. 다른 사람의 공개 지갑 기록은 접근 가능한 내보내기 도구에서 해당 공개 주소를 넣어 파일을 확보해야 하며, 도구별 지원 범위와 이용조건을 확인해야 해.
